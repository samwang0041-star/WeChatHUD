## 判断要求（输出 JSON）

```json
{
  "is_ask": true或false,
  "ask_type": "yes_no|send_file|review|decide|info|schedule|action|none",
  "summary": "一句话概括对方需要你做什么（限20字）",
  "deadline_hint": "从消息提取的时间要求（如有，否则null）",
  "urgency": "routine|timely|urgent",
  "confidence": 0.0到1.0,
  "related_pending": "如果与已有待决项相似，填写该项摘要，否则null"
}
```

## ask_type 说明（只能从以下取值中选择，禁止自创类型）
- yes_no: 需要做是/否决策
- send_file: 需要发送文件/资料
- review: 需要审阅/确认
- decide: 需要做复杂决策
- info: 需要提供信息
- schedule: 需要确认时间/安排
- action: 需要做具体行动
- none: 不需要回应

## urgency 说明
- routine: 不急，随时回复
- timely: 有时间预期，今天内回
- urgent: 措辞紧急或boss催促

## 角色影响判断的规则
- boss: 反问句算ask（"这个没问题吧？"=需要确认）；感叹句看情绪（"辛苦了"≠ask，"怎么还没好！"=ask）
- key_client/client: 任何疑问句都算ask（客户不能不理）
- family: 涉及健康/安全/钱 → urgency=urgent
- colleague: 只有明确请求/问题才算ask
- supplier: 节日问候/营销不算ask
- 如果算法检测到紧急词但你判断不是ask，confidence应降低到review区间让人工确认

## 负面示例（不是ask）
- 银行/系统通知："您的信用卡消费XXX元"
- 转发文章/链接（不附带提问）
- 群聊中非说给用户的讨论
- 讽刺/反语："你都没事做的吗"（质疑，不是ask）
- "收到""好的""OK"单独出现
- 自述行动："我去开会了""我到了"
- 拍一拍/表情包/红包感谢

## 正面示例（是ask）
- "你要不要一起去"（征询 → yes_no）
- "你来不来"（征询 → yes_no）
- "方案发我看看"（请求 → send_file）
- "这个进度没问题吧？"（boss反问 → review）
- "帮我确认一下"（请求 → action）
- "周五的会议改到下周可以吗"（schedule）

只输出JSON，不要任何其它文字、markdown围栏或解释。
