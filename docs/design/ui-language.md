# WeChatHUD UI 语言规范（v1，2026-09-09）

依据：产品目标（零猜测引导、每模块 1/2/3 级界面有明确逻辑、原生 macOS 体验）+ 高星开源设计模式检索（Linear 的信息密度与三级导航、Raycast 的"搜索即入口"、GitHub Primer 的语义色 token、Apple HIG 的原生控件优先）。本文是后续每个模块整改与验收的依据；与截图走查结论互相引用（见 docs/qa/2026-09-08/workspace-audit/audit.md）。

## 全局不变量（任何页面不得违反）

1. 布局对齐：卡片 header = 图标+标题居左、主操作按钮居右；正文内容左对齐；仅列表空态允许居中。页面大标题与内容列同左缘（参照"使用指南"header 的 leading 锚定修复）。
2. 层级用间距与字重表达，不用嵌套边框：同一卡片内只允许一层分组背景；分段控件最多出现在一个层级。
3. 语义色只走 CompanionPalette：accent=可推进的主操作；red=仅破坏性操作（且必须有二次确认）；orange=需要用户行动的警示；secondary text 用于解释，不用 red/orange 表达普通信息。
4. 每个可操作控件都有 accessibilityLabel；浮层类内容（卡片/展开区）必须留在宿主窗口 AX 树内（参照简报卡从 popover 改原位展开的先例）。
5. 动画：非线性、有物理感、方向不对称。
   - 形态（compact → peek → extended / notification）走弹簧：悬停先 peek（同高加宽，不打开收件箱），短停留或点击再展开。展开 response 0.42 / damping 0.82（略欠阻尼，从刘海"弹"出来）；窗口收起仍是临界阻尼 0.26 / 1.0 以免尾段抖像素。SwiftUI 侧 closeMorph 用 0.30 / 0.88。
   - 就地显隐（disclosure、toast、行内展开）用强 ease-out cubic-bezier(0.23, 1, 0.32, 1)：用户已经做出动作，曲线要在起始段立刻响应，只把落点软化。设置页切换 0.16s（一天几十次，短于就地 0.18s），工作台行内 0.20s；只有会撑开浮岛窗口的展开跟岛的 openMorph 弹簧走，避免行和窗口两套时钟。hover 洗层 0.10s easeOut。
   - 入场与离场都走 ease-out，离场更快（`CompanionMotion.enter` 0.25s / `exit` 0.16s）。ease-in 禁止用于 UI：它把用户正在看的第一帧拖慢，即使时长更短也像输入延迟。
   - 持续状态呼吸只走 `CompanionMotion.pulse()`（easeInOut + autoreverses）。一次性 ease-out 再从头播放会在每圈起点跳一下。
   - 岛下独立 toast 窗口：首次出现 250ms 强 ease-out + 从岛向下 scale 0.95；替换不动画；离场 160ms。Reduce Motion 与岛被藏起时瞬切。
   - 工作台可点卡片、筛选胶囊、空态 CTA 走 `CompanionPressStyle`（0.96 按压）。全宽选择行（侧栏、待办、关注谁、准入范围、添加联系人列表、使用指南 FAQ、洞察侧栏/折叠头）走 `CompanionRowPressStyle`（只降透明度、不缩放）。全宽条上缩放会读成橡皮。
   - 状态、错误、回执行走 `companionStatusReveal`（scale 0.98 + opacity，与 islandDetailReveal 同一物理），禁止第三套 scale。键盘操作、搜索输入、系统 DisclosureGroup 不动画。
   - 面板形态由合成器遮罩驱动（固定的 island stage + CALayer mask），窗口在动画期间不 resize（首次扩张一次性付掉 stage 成本；若新的 island 比当前 cover 更大，一次实跑会先扩大 stage 再动画，属于预期的一次性窗口 resize）；display link 只在弹簧未收敛时运行。
   - 按压必须有可见反馈。卡片/胶囊：scale 0.96（可用区间 0.92–0.97），配 100–140ms 曲线。全宽选择行：同一时长的透明度洗层，不要 scale。
   - 岛上纯图标热区 22×22。`IslandIconButtonStyle` 不自带尺寸，调用点必须给 frame；父级 `.animation` 不能代替折叠内容上的 `companionStatusReveal`。
   - 尊重 reduceMotion：所有动画与 hover 触感一并关闭；尊重 reduceTransparency。
   - 悬停进入 peek 补一次触控板轻反馈（`.levelChange`）。边框：离开 compact 后 0.5pt 白发丝线；VIP 紧急用琥珀/红色光晕（只变色相、不改变不透明度）；AI 整理中 30Hz 扫光。

## 模块三级界面逻辑

每模块按"1=列表/总览，2=模块内分区 tab，3=详情/编辑"组织；3 级永远通过展开或右侧详情呈现，不新开窗口：

- 工作台：1=今天总览（分区卡片：需要回复/我要做/等对方）；2=无（保持单页）；3=行内展开（消息原文 disclosure、简报卡原位展开）。
- 助理：1=会话列表+当前上下文；2=回复草稿/承诺/洞察（侧栏导航）；3=对话详情工作台（固定 500 高，内部滚动）。
- 关注的对话：1=联系人列表+筛选（全部/重点/关注/仅资料）；2=通讯录/整理建议/屏蔽规则/静音管理；3=右侧详情面板（跟踪策略/AI 画像/操作）。
- AI 与提醒：1=三分区单页（分析与建议/提醒方式/AI 服务）；2=分区即 tab；3=AI 服务管理（跳转详情面板）。
- 自动回复设置：1=单页分区（运行状态/风格/护栏/历史）；2=无；3=回复助理跳转。
- 连接与数据：1=微信连接状态卡；2=微信连接/使用偏好/本地资料；3=高级连接与诊断（disclosure）+ 准备引导（原位三检查点，不弹窗）。
- 使用指南：单页长文，步骤锚点跳转对应模块。

## 已走查问题的映射（供复检）

- 悬空居中提示块 → 不变量1（已修复待截图复检）。
- 一卡多功能 → 拆卡原则（导出报告 vs 记录回溯，已修复待复检）。
- 删除无破坏性样式 → 不变量3（已修复待复检）。
- 弹层 AX 不可见 → 不变量4（简报卡已改原位展开，已验收）。

## 后续验收清单（每个模块改版后逐项核对）

1. 三级逻辑与本文一致；2. 不变量逐条通过；3. AX 树包含全部可操作元素；4. 空态/错误态/加载态三种状态都有真实内容与下一步动作；5. 通知/浮窗形态的状态在 Preview 演示数据下可复现。

## 材质与光（v2，2026-09-15）

依据：产品负责人要求参考 CleanMyMac 5 的 UI 效果，提升动画质感、交互文案与前端观感。
本文 v1 的排版与层级规则全部继续有效；v2 补的是"表面（surface）如何被光照亮"和"动效如何成组"。

### 一条光源，从上往下

全站只有一个假设的光源，位于页面上方偏左。所有"抬起"的表面必须同时满足三件事，缺一不可：

1. **顶边有一条更亮的发丝线**（`CompanionElevation.topHighlight`，约 5.5% 白）。
2. **面带一条极浅的亮度渐变**：顶部 3% 白 → 底部 1.2% 黑（`bottomShadeOpacity`）。这是"被照到"的关键，纯色填充永远像纸片。
3. **底边有一层柔和阴影**（`cardShadow`，20% 黑 / 半径 14 / y 6）。只允许一层，不允许叠加。

反过来，**凹陷**的表面（搜索框等）走相反方向：顶边暗、底边亮，用 `CompanionElevation.insetRadius`。
同一平面不得混用——一张卡片里如果同时出现抬起和凹陷且没有语义理由，就是错的。

### 模块色

每个模块拥有自己的强调色（`SettingsView.Tab.accentColor`），并贯穿三处，让它成为"你在哪个房间"的线索而不是装饰：

- 侧边栏行前的圆角方块（`CompanionModuleTile`）；未选中时饱和度降到 62%，选中时满饱和度并加光晕与 1.06 缩放。
- 页头同色同形状的方块（34pt）。
- 该页的 `CompanionBackdrop` 环境光、主要按钮与计数徽章。

侧边栏选中行用**本模块色**的横向渐变填充，不再统一用品牌绿：眼睛在读到页标题之前就知道自己在哪个模块。

### 环境光

详情页底色 = `CompanionPalette.canvas` + 一层从顶部散开的模块色径向光晕（`CompanionBackdrop`，强度 5.5%）。
这是"房间温度"，不是彩色背景：超过 10% 就会和卡片抢注意力，`CompanionMaterialTests` 会拦住。

### 动效成组：错峰入场

切页时内容不再整帧跳出，而是按阅读顺序依次到位（`companionStagger(index:)`）：

- 位移 6pt（不是 20pt），淡入 300ms，步进 45ms，整组预算约 240ms。
- 延迟**封顶在第 6 个**，长列表的最后一行不会等一个永远不会来的下一行。
- reduceMotion 下位移与延迟同时消失，内容是"就在那里"，而不是"延迟后出现"。
- 「今天」不再错峰：侧栏切页已经是 160ms 淡入，每天打开的工作台再叠一层会变慢。错峰只留给使用指南。

### 交互文案分层

`CompanionProductCopy` 管"这个东西叫什么"（标签、弹窗标题、回执）；
`CompanionInteractionCopy` 管"用户正在做什么的时候，界面对他说什么"。三条硬规则：

1. **说结果，不说实现**："读取这台 Mac 上已登录的微信"，不是"初始化数据库连接"。
2. **每个等待都要有承诺**：超过约 400ms 的状态必须说清在等什么、等完会出现什么。
3. **每个失败都要有下一步**：绝不出现光秃秃的"失败"。

侧边栏每一行的 tooltip / VoiceOver hint 说明**这页是干什么用的**，不是把标签重复一遍（`CompanionMaterialTests` 断言两者不相等）。
同一句话同时供鼠标 tooltip 与 VoiceOver 使用，两者不会漂移。

### 完成度提示

页面上不能只有"还剩多少"。"今天"在标题旁显示今天**已经处理**的条数（`handledToday`），
且条数为零时不显示——新装用户不该被一个 0 迎接。

### 验收补充

除 v1 清单外，材质相关改动必须同时满足：

1. `CompanionMaterialTests` 全绿（光源方向、悬停幅度、环境光上限、错峰封顶、reduceMotion 归零、模块色互异）。
2. `ChromeMotionHygieneTests` 仍全绿——任何动画都必须过 `CompanionMotion` 闸门，不得出现裸 `withAnimation(`。
3. 深色与浅色两种外观都截图走查；`--preview-light` 可固定外观。

### 底色强度是算出来的，不是调出来的（2026-09-15 二轮）

模块底色的强度由**两个约束夹住、取最小值**：

1. **按通道极差归一化**：人眼读到的「换房间」是地面通道极差 max(R,G,B)-min(R,G,B)，
   而各模块色极差不同（玉色 97/255、琥珀 179/255）。不归一化的话同一个透明度会让琥珀房间强一倍多。
2. **亮度天花板**：页头副标题就落在色晕最强的位置。上限不从审美来，
   而是从「落在它上面的字必须过 WCAG AA」反解：`ambientLuminanceCeiling`。

参考产品（CleanMyMac）的地面通道极差是 59.7，我们停在 23.5–35.3。
差距是结构性的：它是海报式窗口，色场上只放又亮又少的字；
我们是密排 20 行消息的工作台，它的 60 在我们这里会压到 2.9:1（低于 AA）。

**因此落在底色上的字必须比常规 secondary 亮一档**（`onWashSecondary()`）。
这不是补偿，是让底色能变强的必要条件：用提亮换回颜色额度。
该样式按外观分支——深色 80% 白，浅色走常规 secondary。

实测（渲染像素）：页头 10.0–10.7:1，卡片正文 11.7–16.5:1，AA 门槛 4.5:1。
### 浮岛轮廓：状态驱动的圆角（2026-09-15 三轮）

浮岛三个圆角是**状态驱动**的，不是常量：

| 状态 | 底部药丸 | 缺口内圆 | 顶部外圆 |
|---|---|---|---|
| compact / peek | 22 | 10 | 16 |
| extended / notification / detail | 16 | 12 | 20 |

方向是刻意的：展开后更**方**（它是面板不是药丸），缺口内圆略**增**以继续贴合硬件。

三条硬约束：

1. **硬件几何不参与插值**。缺口宽高来自真实屏幕测量，过渡中必须恒定，否则缺口会滑离刘海。
   只有圆角进 `animatableData`。
2. **动画必须作用在形状本身**。外层 `.animation(nil, value: presentedState)` 会抑制隐式动画，
   只实现 `animatableData` 不够，圆角仍会瞬跳。
3. **弹簧必须对齐窗口帧弹簧**，不是内容 morph。形状跟着帧走，否则圆角领先或落后边缘。

所有绘制轮廓的地方（岛体、光晕、扫光、内容 chrome）都从 `IslandChrome.radii(for:)` 读同一份值，
并由源码扫描门禁止任何调用点再写字面量——曾经有四处各自写死，其中 chrome 那一处漏改。

## 简洁优先（v3，2026-09-15）

v2 把 CleanMyMac 的「每个模块一间房」搬了过来：18 种强调色、侧栏彩色方块、页头 34pt 色块、滤镜做成发光主按钮、切页换房间色温。那套语言适合海报式窗口。WeChatHUD 是密排消息的工作台，再加一层彩虹，工作本身就被抢走了。

v1 的排版与层级、v2 的顶光材质与动效闸门继续有效。v3 改的是**什么东西配得上颜色**。

### 一条强调色

工作台只有 `CompanionPalette.accent`（玉色）。红 / 橙只留给破坏性操作和需要立刻行动的警示。侧栏图标走应用强调色，不再给每一行固定一种色相——这是 macOS 侧栏的默认约定：固定色只在颜色本身有含义时使用（例如 VIP）。

切页不再换房间色。底色洗层仍在，但是同一层玉色大气，不是十八种色温。

### 侧栏是符号，不是色块

选中行：安静的玉色浅洗 + 半粗符号。未选中：次要色符号。没有饱和方块、没有 1.06 缩放、没有描边光晕。品牌方块只出现一次，在侧栏页头。

页头不再重复那个 34pt 色块。标题和一句副标题就够确认你在哪。

### 滤镜不是主按钮

选中的筛选胶囊用浅洗 + 玉色字，不白字填满、不带光晕。页面上只有真正的下一步（例如「添加关注」的系统 prominent 按钮、引导页的继续）才是填色动作。

`CompanionGlowButtonStyle` 的光晕收到耳语级，只留给引导这种「屏幕上只有一件事」的时刻。

### 签名还在浮岛

产品被记住的东西是吸顶黑岛 + 玉色，不是工作台的彩虹房间。浮岛上的选中态可以继续是填色玉胶囊：黑底上那是品牌，不是噪音。

### 验收

1. `testWorkspaceSharesOneAccent` 全绿：所有 `Tab.accentColor` 都是同一条玉色。
2. 侧栏目视：没有一排彩色方块；选中行能认出来，但不会比消息列表更抢。
3. 待办 / 今天 / 关注谁的筛选胶囊看起来像分段，不像三个主按钮。
4. 深浅色都还过 WCAG AA（v2 的洗层对比度闸门仍在）。

## 平台标准（v4，2026-09-16）

前三版管的是这套自有视觉长什么样。第四版接的是**平台义务**：Apple 对 macOS App
的规定动作。完整走查与整改记录在 `docs/design/macos-hig-audit.md`，这里只留结论。

### 菜单栏是 UI 的一部分

`LSUIElement = true` 只意味着没有 Dock 图标，不意味着没有菜单栏：工作台被激活时，
屏幕顶部那条菜单就是本 App 的。它必须按 macOS 的约定长——关于/服务/隐藏、
⌘W 在文件菜单、⇧⌘Z、⌃⌘S、⌃⌘F、窗口菜单三项。

**服务菜单缺失不是「少一行」**：它是本 App 能否被别的 App 用「服务」把文字送进来的开关。

菜单结构由 `MainMenuTests` 断言，不靠目视。

### 系统辅助功能开关必须都接

`CompanionMotion` 接减少动态、`reduceTransparency` 接降低透明度，
`CompanionAccessibility` 接另外两个：**提高对比度**与**不用颜色区分**。

关闭时零变化（渲染测试断言像素完全相同），打开时才加深发丝线、加粗卡片描边、
把状态灯从「三个色相」变成「三种轮廓」。

### token 是 static 就等于没有依赖

SwiftUI 因为 body 里读到的东西变了才重绘，而读一个 static 不建立依赖。
凡是外观由 `CompanionAccessibility` 算出来的视图，都要经
`.companionDisplayGeneration(_:)` 拿到一个会变的代次。

这条不只适用于新加的两个开关——它解释了为什么旧的 Reduce Transparency
在预览里「看起来能用」其实是巧合。

### 大字号不许钉死在默认档

`.dynamicTypeSize(.large)` 与「忽略系统设置」在用户那里是同一件事。
允许区间是 `.large ... .accessibility2`：下限是浮岛固定高 chrome 的实测尺寸，
上限是走查过的最大档。
