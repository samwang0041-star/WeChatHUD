# 微信聊天伴侣：逐模块三级界面设计

状态：设计与实施中，不是全量验收通过证明。2026-09-08。

## 设计依据与统一约定

当前原生页面已逐页截图，见 [本轮界面审查](qa/2026-09-08/workspace-audit/audit.md)。保留应用现有青绿色、原生侧栏和系统控件；参考 [Maccy](https://github.com/p0deje/Maccy) 的键盘检索与主次动作、[Rectangle](https://github.com/rxhanson/Rectangle) 的简洁设置分层、[boring.notch](https://github.com/TheBoredTeam/boring.notch) 的短提示与展开操作节奏。只借鉴交互思想，不引入这些项目的代码或素材。本轮重新读取了三者公开仓库，未运行第三方应用。

一级是模块入口与总览，让人知道有什么、先处理什么；二级是选中对象或设置类别，让人理解情况并执行一个主操作；三级是来源、编辑、确认或高级选项，只在需要时打开。不是所有任务都必须连续点三次：高频可逆操作可在一级完成，并给撤销；三级不是把必要信息藏起来。

- 工作台：今天、待办与跟进、我的承诺、回复草稿、聊天洞察、每日简报。
- 助理：回复助理。会话的上下文与回复属于助理任务，可从任意工作台事项直接到达。
- 偏好设置：关注的对话、AI与提醒、自动回复设置、连接与数据、使用指南。
- 原有路由标识保持不变；页面名称与入口职责先统一，避免设置、运行、记录混为一个动作。
- 普通正文13–15pt，次要说明至少11–12pt；不把原浮窗9pt布局直接放大到工作台。
- 每个二级页保留对象名称和来源，返回时保留筛选、日期、选中行、滚动位置和未发送文字。
- 同一个操作只放一个明显主按钮。不可逆发送需确认具体收件人、内容；可逆状态变更直接反馈并可撤销。
- 未同步、无数据、正在整理、整理失败、已保存、保存失败、待确认、未确认发送分别表达，不混为“成功”。

## 一眼就懂的验收要求

每个入口使用普通用户熟悉的名称，首屏必须说清当前情况和下一步。主操作只保留一个清楚的动词；解释不能依赖术语、工具提示或阅读指南。原话、识别依据和高级设置按需展开，不能隐藏完成当前任务必须知道的信息。逐页用真实点击验收，不以布局截图代替操作闭环。

## 各模块一、二、三级

| 模块 | 一级：看到什么 | 二级：如何展开与操作 | 三级：何时出现 | 状态与返回逻辑 |
|---|---|---|---|---|
| 今天 | 需要回复、下一项到期、重要消息；连接异常仅在需要时提示 | 打开一条消息，看到来意、为什么需要关注、建议下一步 | 展开原文、稍后提醒时间、处理记录 | 已处理可撤销；返回原列表位置，不把知会类@计为必须回复 |
| 聊天助理详情 | 从消息、事项或草稿进入，保留明确会话与触发消息 | 先给上下文和建议，再显示原文对话及回复输入；生成建议、采用、编辑 | 来源上下文、替换现有草稿确认、发送确认与回执 | 使用原消息ID，不能按会话随便取另一条；发送失败保留文字；未取得回执不显示已发送 |
| 待办与跟进 | 按我要做、等对方、共同推进筛选，展示标题、责任、期限 | 选中事项展示背景、负责人、交代人、当前状态；主动作随责任变化 | 来源讨论、调整责任、忽略说明与恢复 | 完成与忽略可恢复；写入失败不移走事项；返回保持原筛选 |
| 我的承诺 | 按已到期、今天、之后分清轻重；搜索与进行中/完成筛选 | 展示承诺内容、答应谁、截止时间和下一步；明确“标记完成”按钮 | 原话与识别依据；取消确认；后续可支持修改期限 | 置信度不占主视图；完成状态与原始记录分开；已到期仍提醒 |
| 回复草稿 | 收件人、最后修改、内容摘要、未保存提示 | 单条草稿编辑，主动作“继续回复”；保存状态清楚 | 替换当前回复确认、删除确认、来源对话 | 切换不丢文字；保存失败保留编辑；未经发送确认不进入微信 |
| 聊天洞察 | 当前范围、关键结论与可追溯的会话入口 | 选择会话与日期：发生了什么、参与者、未决问题、下一步 | 具体原文、统计口径与时间分布、继续回复 | 切换日期清理旧结果；无数据不推导无风险；AI失败与本地统计分开 |
| 每日简报 | 日期、当日重点、未完事项与可读小结 | 展开某项进展，看到来源和可执行操作 | 来源对话、导出/复制预览、历史日期 | 前后日期保留一致口径；复制不等于发送；事实整理与AI解读明确标注 |
| 回复助理 | 当前运行状态、处理范围、待确认数、主动作开始/暂停 | 待确认回复队列与本次活动；每条显示对象、理由和处理结果 | 编辑回复、发送确认、失败详情、取消待发送 | 开始整理与允许自动发送明确区分；运行状态放运行页，偏好放设置页；结果持久可追溯 |
| 关注的对话 | 可搜索列表，重点关注/关注/仅保留资料有清楚含义 | 选中对象显示关注状态、提醒时机、备注与关系摘要 | 编辑、添加、账号信息、屏蔽或删除确认 | 原始账号ID默认收起；保存后立即反馈；移除说明影响范围，不误删微信联系人 |
| AI与提醒 | 当前服务状态；分析与建议、提醒方式、AI服务三个清晰分区 | 选择分区后只展示相关开关或服务配置 | 高级连接、生成偏好、数据说明 | 切分区不丢输入；自动保存有结果，失败可重试；不把填写配置说成验证成功 |
| 自动回复设置 | 当前策略：先确认或允许低风险自动发送；范围摘要 | 调整风格、排除范围、等待时间与频率 | 严格程度、限制解释、发送键等高级配置 | 修改偏好不暗中开始运行；所有当前限制准确反映代码，不用长段话弥补错误命名 |
| 连接与数据 | 微信连接状态、当前账号与最后同步时间 | 微信连接、使用偏好、本地资料三个分区；连接/切换账号任务及系统操作与通知权限的实际状态 | 高级诊断、导出、迁移恢复 | 优先定位当前登录账号；等待检查再继续；保存失败不重启；缺读取条件必须明确说明，不能假报连接成功 |
| 使用指南 | 开始使用、常见问题、快捷操作 | 一项问题配简短步骤和直接跳转按钮 | 原生系统设置、诊断说明 | 只描述已实现能力；不要求普通用户理解API、JSON或数据库文件结构 |

## 跨模块连续性

1. 今天 → 当前消息详情 → 上下文 → 生成建议 → 编辑 → 确认发送 → 回执。每一层都绑定同一个会话和源消息。
2. 对话承诺 → 我的承诺 → 到期提醒 → 查看原话 → 标记完成。AI识别和用户确认分开，提醒不会因为过期而消失。
3. 草稿 → 继续回复 → 若已有输入则询问替换 → 确认发送。取消替换不改任何文字。
4. 偏好设置 → 自动保存 → 可见成功/失败。离开页面时处理待保存状态，后台验证返回时不能覆盖后来修改。
5. 任一能力不可用 → 解释缺少什么 → 直接恢复入口 → 重测真实状态。只改变提示文案不算能力修复。

## 本轮落实顺序与验收

- 先修正在真实使用中发现的断路：群@来源身份、历史消息上下文、当前微信账号识别。测试覆盖精确来源和失败分支。
- 将回复助理运行页从偏好设置移出，统一运行页与设置页名称；保持旧路由和深链。
- AI设置拆为清晰分区，联系人详情把实现信息收起，帮助说明与实际能力一致。
- 重做承诺与日报在工作台的字号、层级和主次操作，不再沿用紧凑浮窗的密度。
- 后续逐项完善草稿主从布局、助理详情与洞察回到来源的连续性，以及所有二三级返回、键盘、窄窗口和深浅色。

验收必须覆盖：每个一级入口；每类二级选择；每个三级关闭/取消/确认；保存失败、AI失败、权限拒绝、无数据；返回后保留上下文；实际微信读取；真实发送回执；新Mac首次连接。当前后两项及操作权限冲突仍未通过，不能将此设计文档当作发布验收。
