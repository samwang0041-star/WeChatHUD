# 密钥准备真机验收清单（待用户授权后执行）

前提：以下步骤会对真实 WeChat.app 做一次性重签（ad-hoc + get-task-allow）并扫描微信进程内存提取密钥。按约定，未经用户明确授权不执行。重签只影响本机调试权限，不改聊天数据；恢复官方签名可通过重装微信。

## 步骤与证据

1. 前置：正式 .app（非 Preview）运行；微信已安装并登录；备份当前 entitlements（codesign -d --entitlements :- 输出存档）。
2. 进入 偏好设置→连接与数据→微信连接，确认标题为“还差最后一步准备”，三检查点可见，无技术术语暴露。
3. 点击“开始准备”：出现确认框（说明一次性签名、微信需重启登录）。同意前确认 codesign 未被调用（无进程）。
4. 同意后：检查点1变为完成；若微信原签名已含 get-task-allow 则跳过重签直接进入扫描（阶段机 idle→extracting）。
5. 用户完全退出并重新打开微信登录；app 检测到新进程+唯一进程证据后自动运行 keytools 二进制（≤120s）；检查点3出现进行/完成状态。
6. 成功证据：~/.wechat-hud/keys/all_keys.json 生成（目录0700、文件0600）；SyncConfig.keysFilePath 指向该文件；连接卡变“微信已连接”；消息列表出现真实摘要。
7. 失败路径：task_for_pid→自动重签并进入“重新登录微信”等待，最多一轮，再失败显示白话错误与重试；校验失败显示重试入口，不落盘任何密钥文件。
8. 安全回归：全程确认不发送任何微信消息、不上传任何数据（扫描为纯本地内存读取）；密钥文件只落本机。
9. 收尾：重签后的微信保留 get-task-allow 属预期；记录于审计文档，附 entitlements 前后对比与二进制 SHA-256。

## 验收判定

全部步骤证据齐备且连接达到 .ok 后，才可把“首次使用引导（数据库访问授权）傻瓜化”标记为真机验收通过；Preview/单元测试证据只覆盖编排逻辑。
